# Robustness integration result

Date: October 26, 2026 (America/Chicago). Status: local implementation candidate; not deployed.

**Release update — October 27, 2026:** deployed to [staging](https://staging.docketstamp.com) at `a6f36854c8403f78d645e8e4e71d1d1fbee3376e`. The rollout succeeded with 100% traffic, all nine indexes are ready, dedicated staging signing is configured, and 13 public smoke checks passed. See the [staging release record](staging-2026-10-27/RELEASE.md). Production remains unchanged. The original implementation assessment below is retained as dated baseline evidence.

The founder authorized Luna agents to execute the [design outline](../../DOCKETSTAMP_ROBUSTNESS_DESIGN_OUTLINE.md). Three native Luna workstreams implemented checkout authority, fulfillment convergence, and customer continuity, followed by renderer, privacy and reporting slices. The primary agent integrated their changes, reviewed authority boundaries and ran offline and mounted-browser checks. This report supersedes intermediate workstream verification notes where later integration resolved a fixture or added a check.

## Delivered behavior

| Area | Local candidate behavior |
| --- | --- |
| Checkout | Verified authentication establishes account ownership; body-supplied identity is ignored. A guest capability scopes attempts. Stable request identity is bound to validated material, a frozen snapshot and a server quote. Supersession requires server-confirmed cancellation; unresolved capture races block replacement and hold fulfillment for review. Canonical attempt and order mirrors advance transactionally without delayed writes downgrading paid states. |
| Fulfillment | Paid, free and audited operator recovery converge on the authorized snapshot-bound dispatcher. Provider acceptance repairs durable order/outbox records. Deterministic follow-on work retries separately, so a receipt failure does not resubmit a letter. Ambiguous non-idempotent effects require attention instead of blind replay. |
| Customer continuity | Meaningful Back/Forward transitions preserve compatible values. Recovery is tab- and account-scoped; signatures and postal evidence must be renewed after reload or material changes. Prefill and stage parameters are scrubbed from the visible URL after consumption. A stale async response cannot overwrite a newer draft. |
| Address and final review | Explicit normalization review precedes confirmation. Server-signed address evidence binds role, address, revision, provider mode and expiry. The final review displays the actual frozen HTML before exposing payment controls. |
| Physical document | Preview and print share fixed Letter geometry and typography. The provider owns the reserved top address region. A conservative browser/server preflight blocks oversized content before a payment intent or order is created; content is not shrunk or rewritten. |
| Privacy | Google, Meta and legacy telemetry bridges require consent, respect GPC and restrict third-party events to generic fields on permitted public surfaces. Document, account, stage and admin surfaces suppress third-party tags; route/query changes clear vendor queues. Internal typed operational telemetry remains separate. |
| Operations | Published reports expose date, timezone, environment, channel, source freshness and completeness. Source reads are bounded, historical joins are targeted, and missing costs/spend stay unknown. Contribution before and after acquisition is distinguished. Updates use the existing explicit audited projection action. |

No notice prose, prices, product categories, international dispatch, or historical frozen snapshots were changed. The six canonical invariants remain required. This candidate does not implement every future item in the chapter: durable cross-session saving, live acquisition experiments, scheduled reconciliation ownership, retention/restore drills and exact-build release promotion remain future work.

## Integration evidence

- The complete `npm test` command passed offline with isolated in-memory mock Firestore, mock payments and `staging_mock_cass`. The run contained 268 TAP tests with zero failures, plus the existing standalone assertion/audit scripts. `test:robustness` is now part of the normal command; its latest run contained 38 passing tests.
- `npx tsc --noEmit --pretty false`, `git diff --check` and `npm run audit:credentials` passed. Credential hygiene scans tracked files; it does not certify external environments.
- Exact-source `npm run build` passed, including compilation, type/lint checks and page generation. Public Google font downloads required network access. Firestore used its real SDK with `FIRESTORE_EMULATOR_HOST=127.0.0.1:9` and absent build credentials; payment/postal keys were placeholders. The first isolated build attempts correctly failed on unavailable font DNS and then the production mock-store prohibition; neither protection was removed. The final build did not alter source or deploy anything. Build log: `/private/tmp/docketstamp-robustness-final-build.log`.
- Mounted browser checks used fictional details on a local mock server. They verified prefill recovery and URL scrubbing, explicit ZIP+4 normalization review, confirmation of simulated address evidence, signature readiness, frozen snapshot review, and browser Back from frozen review to delivery to signed review. No payment was submitted and no mail or email was sent.
- A 27-case browser stress render measured 816 × 1056 CSS-pixel sheets across nine notices and three tiers. Twenty-four stress renders fit the body; the three long credit-dispute renders extended beyond the body. The new preflight rejects those and conservatively rejects three close maximum-field deposit cases. All nine ordinary-length notice fixtures pass the estimate. These are finite fixtures and a conservative estimate, not proof that arbitrary accepted strings fit every browser or provider renderer.
- Browser review found and resolved a client/server property-address composition mismatch: interpolation and validation now share idempotent composition. Both preview and frozen review show `300 Elm St, IL`, and signed staging evidence produces an explicit simulated stamp. Browser review also caught the unscaled snapshot iframe; its fixed-size page now scales to the modal and offers a larger review. The [saved local screenshot](frozen-review-local.jpg) uses fictional data.
- The mock browser exercise exposed a real-provider lookup for a local mock intent during supersession. Supersession now requires persisted order/attempt mode, matching intent bindings and matching runtime mode. Local pending mock orders resolve without Stripe calls; unknown or mismatched modes stay blocked. Legacy attempts can use the server order's explicit stored mode. Offline regressions cover these distinctions; Continue is disabled during stale/unresolved recovery.

Offline logs are local temporary artifacts (`/private/tmp/docketstamp-robustness-final-tests.log`). Finite physical measurements are retained in [browser-physical-measurements.json](browser-physical-measurements.json). Individual contracts, tests and findings are described in the [checkout](checkout-result.md), [fulfillment](fulfillment-result.md), [continuity](continuity-result.md), [server review](server-review.md), [physical parity](parity-result.md), [physical preflight](physical-fit-result.md), [reporting](reporting-result.md) and [privacy](marketing-privacy-result.md) results.
