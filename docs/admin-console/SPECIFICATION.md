# Overhaul specification

Requirements IDs in this document are mapped in [COVERAGE.md](COVERAGE.md). Shared event/metric semantics are normative in [CONTRACTS.md](CONTRACTS.md). Preserve all six project invariants and existing compatible customer/operator capabilities (R01).

## Recommended operating model (R02–R05)

The CEO opens Overview to answer: money verified, notices progressing, exceptions requiring action, journey friction, acquisition efficiency, and evidence confidence. These are linked views of the same scoped records. Financial and postal truth come from durable authority facts; browser observations explain behavior. Missing evidence remains visible.

Daily: review urgent obligations and payment discrepancies; investigate the highest-priority cohort failure; confirm current evidence freshness. Weekly: compare mature acquisition/offer cohorts and cost coverage, record one decision/hypothesis and evaluation window. Incidents have an owner, severity, impact count, age, acknowledgment, next action and evidence-based resolution. Acknowledge and resolve are different. A retry click alone cannot resolve an incident.

Navigation:

| Area | Main work and evidence |
| --- | --- |
| Overview | Five KPIs, ordered observed journey, top exceptions, compact channel rows, confidence strip. |
| Orders & postal obligations | Server-paginated search beyond latest 50, all statuses/classes, independent money/postal/email/proof state; single correlated detail. |
| Journey & acquisition | Cohorts by notice, tier, device, entry surface, original and latest acquisition, agent-stage handoff, validation/CASS/payment failures; spend and attribution coverage. |
| Offers & recovery | Create/preview/distribute/pause/version offers, quota/budget, exposure and redemption, free/paid/refund/fulfillment. Draft-safe recovery tools. |
| Money & reconciliation | Captures/refunds/disputes, pending/mismatched transactions, actual/estimated cost components, spend import provenance, cash vs cohort views. |
| Reliability & data | Correlated incident worklist; request/error/latency trends for stage, verify-address, lock, Stripe webhook, Lob submit/webhook, proof and receipt; projection watermarks/rejections/reconciliation. |
| Controls & planning | Effective configuration with real scope, recent probes and owner; allowlisted flags with consumers/effect, rollout history; separate assumptions simulator and decision log. |

No separate generic CRM, support vendor, warehouse, tracing vendor or experiment platform is needed initially. Use structured server logs with correlation IDs plus bounded diagnostic summaries in Firestore; link into existing hosting logs where authorized. Capture route-level request counts, error classes and duration histograms, not raw request bodies. Add a vendor only after a demonstrated retention, query cost, latency or tracing requirement cannot be met economically (R06).

## Executive composition and interaction (R07)

[WIREFRAME.html](WIREFRAME.html) is an inspectable static proposal. At desktop 1280×720 target: 56px scope header, 160px left rail, 5 compact KPI columns, exceptions and journey side by side, then acquisition and confidence. Use 16–24px gutters, 14px default data text, 12px minimum secondary text, tabular numerals, 28px KPI values, muted neutral background and navy ink. Amber means review/uncertainty; red means active obligation/risk, green requires recent success evidence. No decorative status card above the business summary.

Global scope header: environment and independent Stripe/Lob/CASS modes; dates/timezone; customer-class filter; last refresh; data cutoff and partial indicator. Scope persists through drilldown, browser back and reload; URL contains only nonsensitive scope. The default operational exception list deliberately spans all open obligations and labels that scope. Switching production/staging changes the data source explicitly, not a cosmetic filter. No automatic production writes.

Five KPI cards: verified independent paid orders, net customer collections, live postal acceptance (with pending), observed paid-session conversion (n/d, maturity), open urgent obligations. Click any number to open the exact paginated evidence query; drawer includes definition, authority, date basis, exclusions, freshness and download permission. Show repeat orders separately from converting sessions. Contribution is a compact acquisition column when cost coverage permits, otherwise “Unavailable — costs missing”, with estimated scenario in a separate view.

Journey row: entry → selected → details ready → signed → locked → attempted → paid → accepted. Display actual counts, denominator, missing links, and inference badge for inactivity. Offer/staged/direct entries may skip observed upstream steps; show alternative paths and independent reaches rather than invent prior completions. Hover is optional; keyboard/button drilldowns provide all content.

Exception rows: priority, affected orders/value, age/oldest, reason, evidence freshness, owner, next action. Order detail opens within two interactions, correlates order/docket, immutable snapshot hash/version, exact charged/discounted total, payment/refund/dispute facts, dispatch attempts and mode, provider timeline, proof/return-receipt and receipt-email attempts, acquisition/offer history, and action audit. No address/document body on overview.

Channel rows: original-source grouping default, with latest-qualified-touch switch; sessions, mature converting sessions, paid orders, net collections, spend with coverage, contribution actual/estimated/missing, join coverage. Totals do not come from visible sample rows. A notice detail gives failure counts by validation class, time-to-complete distributions and n; no automatic unsupported legal/business recommendations.

## Investigation, freshness and usability (R08–R10)

- >=1024px: left rail and two-column exception/journey layout. 768–1023px: collapsible rail, KPI wrap, single investigation column. <768px: one 48px nav with Overview/Orders/More, scope sheet, two-column KPIs then urgent exceptions; journey rows vertically; table rows become readable cards or a labeled scroll region. At 320px no page-level horizontal overflow. Do not duplicate bottom and horizontal tab navigation.
- All charts have a text/table equivalent, visible labels, accessible names, keyboard drilldowns; color is redundant. WCAG 2.2 AA target; verify computed contrast, 200% zoom, keyboard-only, screen reader headings/table labels, reduced motion, 44px primary touch targets. Focus traps/escape/focus return in drawers/dialogs; announce async result politely without stealing focus.
- Loading: per-panel skeletons with labels; no zero counts or green healthy states. Empty: “No qualifying records in this scope”, with scope/exclusion evidence. Missing instrumentation: “Not measured”, not empty business activity. Error: retain last success with timestamp and error boundary; retry is read-only. Stale: amber last measured time; stale action preconditions must revalidate. Partial: show covered interval/shards and missing sources; suppress unsupported comparisons/rankings. Unauthorized: no leaked counts, return path for authorized sign-in. Offline: cached evidence visibly stale, writes disabled.
- Proposed freshness: financial/obligation projection target <5m after durable receipt, browser funnel <15m, spend/cost daily when source available. Health unknown after twice expected check interval; these are configurable defaults requiring operations approval. No traffic is “no recent observation”, not healthy or failed. Record configuration, last attempt, last success, sample count, result and age for each integration. Never derive provider connectivity from a key existing or incident absence.
- Measurable usability gate on synthetic data: CEO identifies oldest urgent paid-undispatched item in <=20s; explains conversion denominator/classification and data cutoff in <=30s; opens a KPI's exact evidence in <=2 interactions; locates an order older than latest 50 within <=30s; previews an offer and copies an accurate notice-specific link in <=60s. At least 4 of 5 representative operators/tasks succeed without guidance; report n, failures and actual times, not invented pass rates. If founder is sole available operator, record that limitation and require all five task trials without claiming a population result. Review 1280×720, 768×1024, 390×844, 320×640 screenshots for each main state. These are acceptance targets, not prior measurements.

## Commercial controls and continuity (R11–R13)

Preserve percentage, fixed-amount and 100% vouchers, descriptions, expiry, activation, quotas, share links, free dispatch and operator comps. No trial/subscription/referral-credit engine was found in the active notice flow; do not invent one. A later referral label may associate a campaign without silently creating monetary credit obligations.

Offer version: stable offerId/code, version, campaign association, notice/tier eligibility, first/repeat eligibility where supported identity exists, start/end UTC, timezone display, active/paused/archived, percent or fixed cents, max redemptions, per-identity limit if verifiable, reserved/committed subsidy budget cents and max free dispatches, owner and audit. If buyer identity is guest/unverified, disclose inability to guarantee per-person eligibility rather than fingerprint covertly. Existing code values and valid entitlements must migrate compatibly; refuse ambiguous new rules on legacy codes until a reviewed mapping exists.

Offer composer previews all three actual registry prices: list, discount, payable, actual/estimated postage+processing costs, missing costs and estimated contribution. Cap amount at zero; zero offers may still incur postage. Show processor minimum-amount constraints for small positive totals; validation must yield an explicit supported payable result rather than fail later. An authorized operator can approve a negative estimated contribution within recorded budget; do not silently remove the commercial lever.

Canonical share format `?offer=<public-code>&utm_...` on a compatible notice or home entry. Accept legacy `discount` and `promo` aliases at one boundary; no direct sensitive field values or bearer draft token in campaign links. Parse once into journey state; preserve through chooser→directory→workspace→tier change→checkout, back/reload and valid resume. Explicit offer replacement is visible; no hidden stacking. Code received is not automatically valid/applied: server validation and visible price update required. Unavailable/expired/paused/exhausted/ineligible codes produce a reason and permit normal checkout at clearly accepted price. A material price change after lock creates a new quote/order attempt and human reconfirmation; never mutate a paid snapshot.

Reserve quotas and subsidy budget transactionally at lock against offer version and quote, with proposed 30m reservation TTL. Commit unique order redemption on verified payment or zero-total authorization; release on cancellation/expiry. A PI succeeding after TTL must still be honored at its frozen payable amount; book authorized subsidy/overrun exception, do not discard payment or double-count usage. Prevent new reservations beyond budget; concurrent final-use tests required. Refund adjusts money and offer reporting; default redeemed usage stays consumed to avoid abuse, explicit audited restoration available. Archive preserves historical records and codes cannot be reused ambiguously. Replace destructive deletion with reversible archive in UI while retaining historical API compatibility as a guarded deprecated operation.

Recovery list is “No observed continuation” with observation age, not projected recoverable dollars. Generate a valid link only after selecting an existing eligible offer; verify it and show actual price. Resume links are separate short-lived capabilities with no private data in analytics; require explicit user sharing and supported consent for outreach. Preserve manual copy, never automatically email customers during this project. Measure exposure, link open, application/rejection, reservation, paid/free redemption, refund, live fulfillment and cost coverage. Redemption and before/after comparisons do not prove incremental lift. Experiments need a predeclared hypothesis, randomization unit, exposure, primary metric/maturity, minimum detectable effect/sample plan based on real baseline, guardrails and stop decision. With insufficient traffic use usability and diagnostic evidence; never invent statistical power or lift.

## Authorization and consequential actions (R14–R16)

Extend existing Google/Firebase account-bound auth, but fail closed without secure signing material. Do not broaden privileges just because a person can view the console. Proposed roles: viewer (aggregate and redacted evidence), operator (assigned obligation detail, reconcile, address/proof workflow), commercial (offers/budgets), owner (role/config/comp/replacement execution). Founder approves assignments; current admins map explicitly to owner only in reviewed migration. Named service principals for jobs. Enforce capability and object/environment scope on server, CSRF/origin and method checks, idempotency, validation and rate limits. Client hiding is not authorization.

Every consequential command: preview exact target/effect/environment, expected resource version, price/cost uncertainty, reason, preconditions and authority; then explicit execute with request id/idempotency key; append actor, capability, before/after redacted values, evidence refs, result, timestamp and correlation ID. Persist pending audit before external action and reconcile uncertain results after crash. No raw private document text in audit. Stale version returns conflict/review. Read queries never initiate money, mail, email, repair or analytics backfill.

| Command | Required effect/guard |
| --- | --- |
| Reconcile Stripe/Lob | Fetch evidence, record facts only. Show “does not initiate mailing”; separate command for dispatch. Missing provider config blocks, never mock success in live scope. |
| Retry technical dispatch | Require payment/free authority, canonical immutable snapshot, valid addresses and current mode; reconcile uncertain prior attempt, acquire lock, reuse idempotency key; block already accepted mailing. |
| Correct address | Preview frozen body/envelope consistency. Material correction creates new human-reviewed snapshot; cannot edit original paid notice silently. |
| Comp/free notice | Canonical template/guardrails/render/freeze path and explicit subsidy authorization; classify free, costs retained. No arbitrary HTML, no bypass of fitness blocker/disclosures. |
| Refund | This package implements visibility/reconciliation and a read-only provider handoff first. Any future money-moving control needs separate authorized scope, PI/refund ID linkage, amount cap and audit; no new automatic refunds. |
| Flags/config | Allowlisted keys with active code consumers, default/effective state, mode, affected surface, expiry, reason, actor and rollback. Stale/dead V3 flag is marked no active journey consumer; arbitrary keys rejected. No unrestricted secret editor. |
| Incident acknowledge/resolve | Owner/reason; resolve only with evidence or explicit accepted-risk disposition, never because a click succeeded. Alert subscription/test remains available behind explicit send action with audit. |
| Offer/budget change | Versioned diff, prospective effect, live reservations honored, explicit scope and role. Archive does not delete evidence. |

## Migration, shadow operation and release (R17–R20)

Add schemas and indexes; no destructive rewrites/deletions. Existing order fields, provider aliases and tokens remain readable via versioned adapters; new writes always include canonical fields. Backfill financial facts only from verifiable provider evidence, not status names; legacy uncertain snapshots/costs/attribution remain tagged unavailable/inferred. Start measurementVersion at cutover and retain old reports as labeled historical data. Do not retroactively claim observations that never existed.

Projection jobs use bounded pagination/cursors and partitioned documents, not full collection scans on every view or giant singleton arrays. Keep raw financial authority retained independently of analytics retention. Proposed analytics retention 90d, aggregate 13 months; freeze implementation of deletion until founder/privacy/accounting requirements are resolved. No automatic TTL for financial/signed document records based on these proposals.

Shadow v1/v2 into separate namespaces. Compare a declared date range, modes/classes and asOf; each difference assigned expected correction vs defect, with evidence links. Required release gate: repeated replay yields same report hash; every synthetic paid/refund/dispatch fact traces to its provider stub; every production authorized sample reconciles or appears in unmatched queue; zero unexplained cash discrepancy in sampled verified scope. If production access unavailable, mark production verification pending and do not represent release as certified. No arbitrary percentage mismatch tolerance for money.

Roll out read models separately from dispatch/auth fixes; flags are environment-scoped and securely administered. Retain last report generation and compatible field readers. Rollback disables new UI/projections/offer reservations without erasing ledger facts; honor already-issued quotes/reservations and in-flight obligations. Never roll back to insecure signing fallback, unauthenticated webhooks or false financial truth. Dispatch worker rollback holds new submissions for review while reconciling pending attempts; do not replay into postal actions.

Open decisions (owner: founder unless named): independent-customer/test account classification; operator assignments; response SLAs/business hours and exception thresholds; privacy/retention and ad export permission (privacy owner); evidence retention and revenue recognition (accountant); source for actual Lob invoices/Stripe fees and campaign spend; offer budget/expiry and first-customer eligibility policies; real return-receipt evidence types and access; approval of synthetic-to-staging-to-production verification window. Defaults above permit implementation with visible unknowns; unresolved privacy/access/external execution requirements block only their dependent release gate, not independent development. Do not request these answers repeatedly or infer them from legacy Send My Notes assumptions.
